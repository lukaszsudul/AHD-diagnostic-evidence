# Resolved-bus model and independent-checker validation

The task-owned slave drives only low or high impedance on resolved open-drain SCL/SDA. It chooses byte/ACK behavior from pin-observed START, bit clocks and transaction identity, not from the master's filtered pins, private state or returned error code. The separate pin decoder checks emitted bytes, clock count and START/STOP events. It checks timing separately from the master's raw cause. Digital input-high delay is cancelled if any low driver reasserts before its scheduled rise; falling edges are immediate in this sensitivity model. A standalone negative unit test passed `MODEL_DELAY_CANCELLATION_PASS` for a 16 ns transient release under a 128 ns rise delay. Neither delayed-input values nor resolved logic model analog 30–70% rise, metastability, ringing, threshold voltage or PCB loading.

Preflight cases passed: clean write `0x60,0xFF,0x05`; complete read `0x60,0xF4,Sr,0x61` with normal terminal master NACK but no slave-error result; missing write DATA ACK gave raw4; missing read REGADDR ACK gave raw2; 256-cycle DATA-ACK stretch succeeded (max wait261); a long low hold gave raw5/timeout1 rather than a fabricated NACK. The final primary grid ran 214 deterministic cases, each in a fresh XSim process with a 30 ms simulated-time and 45 s wall-time watchdog. All 214 have completion markers, pin traces, expected-result checks and no fatal/error log. No refinement cases were executed. The original output-join defect and exact repair are documented separately.

The independent audit classified `114` cases as digitally generic-valid, `50` as digital sensitivity with analog conformity unverified, and `50` as deliberately invalid timing/absent-ACK stress. It found `0` valid-path false NACK, `4` NACKs on intentionally premature ACK release, and `72` raw5 local SCL timeouts. Of the 72 timeouts, 52 are otherwise digitally generic-valid ACK/stretched-clock cases and 20 have analog-input-delay uncertainty; thus generic I²C validity is **not** the same as successful completion under this master's finite timeout. Neither that timeout nor any particular stretch behavior is proven suitable for the NVP6134C by the reviewed data sheet.

The independent checker rejected six injected corruptions: false timing-compliance classification, wrong phase identity, changed pin byte, missing pin clock, stale completion marker and changed result ID. The checker did not use a simulated raw error as the sole truth for bus compliance. Its verdict is `6/6` negative tests PASS. Three earlier checker-only amendments A1–A3 are disclosed in `HARNESS_AMENDMENTS.md`, with affected full-grid reruns; the compiled design and case matrix remained unchanged.

For independent scanner integration, the unchanged master, exact scanner and exact manifest package were compiled with a task-owned pin slave. A 256-cycle Bank5-select DATA-ACK extension completed a fresh simulated scan: generation1, 82 valid entries, 105 transactions, restore verified, zero target NACK. A 2500-cycle hold at the same point produced raw5/timeout1, scanner detail `0x0005FF04`, 37 valid entries, generation0, bank restore verified, zero target NACK. These are *new simulated* counters; they do not recreate the historical hardware generation26 or its raw4 DATA_NACK. Both XSim receipts are in `simulation-receipts/` and their full private logs remain hashed.
