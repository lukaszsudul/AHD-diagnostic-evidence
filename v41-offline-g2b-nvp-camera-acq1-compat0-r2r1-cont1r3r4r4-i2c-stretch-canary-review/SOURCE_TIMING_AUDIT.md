# Frozen master receiver and timing audit

Authority: compiled frozen `rtl/v41/nvp_i2c_fixed_master.sv` SHA-256 `8C916DD7E3967AB22FF0ED90D9BC4533FA50ADE3FB0F4EB620D26B35E93363BF`, exact source commit `09cd7cbb426027acaefd0cf3989579b80a451f3a`. Actual top instance uses `NVP_AUTOINIT_CLK_HZ=62,500,000` and `.I2C_HZ(25000)`; bench asserts these plus `SCL_TIMEOUT_CYCLES=1250`, `BUS_IDLE_TIMEOUT_CYCLES=62500` without override. `DIVIDER=1250`, `TICK_CYCLES=1251`, FPGA period16 ns. Nominal `1250*16ns=20µs` is not a resolved-pin deadline.

Lines 63–101 show exact structural symmetry: separate two-flop `scl_sync`/`sda_sync`, separate candidate and 2-bit count, both initialized high, and the same candidate-change→count1→count2→filtered update logic. This is no designed SCL/SDA filter asymmetry. Nevertheless asynchronous edge phases can yield different observed delays. The task-owned bench timestamps resolved bus, raw input, stage-2 sync and filtered transitions without forcing or altering those nets. `raw_scl`/`raw_sda` external recognition delays are declared sensitivity inputs; falling edges are immediate in the digital model, rising events are cancelled when a low driver returns.

`state_tick` is `divider_count >= DIVIDER` (line151), not simply a 25 kHz ideal half period. In SCL-required high states (lines153–163), if the controller has released SCL while `scl_filtered=0`, lines281–290 reset the divider each FPGA cycle and increment `scl_wait_count`; comparison is against the *old* count before increment, with raw5/timeout1 on threshold. Thus the count includes the slave's extra low interval **plus raw-input, synchronizer and filter rise recognition**, and any phase offset; it does not count every physical low interval from the previous SCL falling edge. A recognized high exits the wait; `state_tick` then advances the high phase after the divider period. ACK is sampled only in `LL_ACK_W_HIGH`, `LL_ACK_REG_HIGH`, `LL_ACK_DATA_HIGH` or `LL_ACK_R_HIGH` at the later `state_tick` **and** filtered SCL high (lines310–360, 379–390), using `sda_filtered`. The filtered SCL edge itself is not the ACK sample edge. Normal read ends with controller-generated NACK and STOP.

`BUS_IDLE_TIMEOUT_CYCLES=62500` is not a universal wall-time counter. `idle_wait_count` increments in `LL_WAIT_IDLE` only while sampled bus idle is false (lines256–274) and in `LL_STOP_C` only while the filtered SDA/STOP condition remains incomplete (lines406–422); it resets when idle is observed/STOP succeeds. It does not increment through every address/data/ACK high or low state. A new accepted command clears `error_cause` (lines240–253), so later restore/verify overwrites the live raw interpretation.

Preflight examples before the frozen sweep: clean Bank5 write and complete register read both succeeded; missing data ACK returned raw4/timeout0; missing read register ACK raw2/timeout0; 256-cycle extra-low at write-data ACK succeeded with measured max wait261. At an extra 1250 cycles in one zero-input-delay phase, the same target produced raw5/timeout1 with max wait1250 and no completed ACK clock; not a false NACK. In that 256-cycle example, resolved SCL rose at `1127360 ns`, stage-2 sync rose `24 ns` later, filter rose `72 ns` later, and ACK sample occurred near `1147448 ns`; these are simulation values, not PCB measurements. A separately compiled negative model test showed that a 16 ns high pulse during a 128 ns delayed-rise wait did not create a stale spurious raw high after the line was pulled low again.

Full grid-dependent latency ranges, timeout transition cases, and any valid-path exception are reported in `CASE_RESULTS.csv` / `TEST_RESULTS.md`; this source audit does not manufacture a single universal physical threshold. The model does not represent metastability, analog RC 30–70% transition, ringing, translator behavior, supply disturbance or actual PCB thresholds.
