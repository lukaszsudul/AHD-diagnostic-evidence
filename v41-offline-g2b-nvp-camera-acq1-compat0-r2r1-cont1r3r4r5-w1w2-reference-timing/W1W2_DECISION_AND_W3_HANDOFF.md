# W1/W2 decision and W3 handoff

## Answer

The unchanged, clean SCAN1 model measured **3,755 FPGA cycles = 60.080 µs** from each successful group-bank `0xFF` write's resolved STOP to the verification read's **initial** resolved START (10/10 groups). This is 139.920 µs below the inspected HI_I2C helper's 200 µs post-write-call wait and 239.920 µs below the inspected I2C_INTERNAL helper's 300 µs wait. The comparison is to source-level software waits, not a measured physical reference-bus STOP-to-START interval. All 10 verify-read STOP→first-entry initial START intervals were also 60.080 µs; they are read-to-read intervals with no 200 µs criterion. Three same-bank group reselections and the successful terminal entry-bank restore→verify had the same modeled gap.

The frozen FPGA image executes a fixed stage-2 AHD1080p25/CH1/VDO1 initialization and an explicit scanner bank-write verification. The pinned reference driver's default module initialization is common setup, `1080P_NOVIDEO` for detected channels, then a chip-ID-dependent port branch. Its 1080P2530 path and EQ are conditional later calls, and input-format detector reads require an explicit caller; neither is an unconditional startup step. The reviewed HI_I2C and I2C_INTERNAL write helpers wait after every write call and discard its return, while the third HI_GPIO_I2C implementation and external transport behavior are unknown. In the detector routine, one bank selection precedes consecutive F0/F2/F3/F4/F5 reads; another post-write delay does not automatically occur before each read. The scoped Bank5 register/value/order differences and all current event mappings are recorded in the W2 files; source behavior is not a vendor bank-settle rule or proof of the physical failure mechanism.

**Recommendation: `PROCEED_TO_W3_MINIMAL_OBSERVABILITY_AND_DELAY_AB`.** A default-OFF, single-variable 300 µs pause after successful scanner-owned bank selection is a useful narrow test of whether added post-selection time changes subsequent verification and read outcomes. It cannot retroactively provide the missing ACK for the Bank5-select write that failed, establish the cause of the 11 historical read REGADDR_NACKs, reproduce every reference write wait, correct any different initialization values or port/mode choices, or establish electrical timing and device settle limits. The event at campaign-0022 group 3 position 8 remains in the 11-event set; events are not confined to the first entries after selection.

## Minimum separately authorized W3 round

Plan one telemetry-development round and one fully signed-off image for both later W4 arms. Preserve first failed operation and terminal error as separate or unambiguously linked records. Each needs raw master cause and timeout, command kind, sequence and phase, valid group/entry/bank/register context, plus per-attempt maximum SCL wait with its ACK phase; collect successful same-kind transaction reference data. Time since verify needs a validity bit and the identity of its origin; a failed selection has no successful current-group verify origin. Store FPGA ticks and convert on the host. This is the minimum to distinguish a read register-address NACK, a bank-select data-byte NACK, SCL waiting and later cleanup effects without importing an unobserved reference transport behavior.

Define a default-OFF option that inserts **18,750 FPGA cycles = 300 µs** after a successful scanner group-bank write, before admitting its existing verification read. Treat this as an *additional* wait, not an SCL-timeout increase or a guaranteed total STOP-to-START target. Set the option only while idle and freeze it for each experimental block. Include successful same-bank group reselections because the scanner actually emits those writes. The same rule should cover successful entry-bank restoration when the existing restore verification follows, including terminal cleanup; it must not delay after a failed write, change failure handling or add a retry. Record this precise scope identically in implementation, sign-off and later W4 analysis. Both arms retain identical autoinit. A future candidate still needs resource and timing sign-off; inherited post-opt LUT 20,186 versus ceiling 20,384, routed LUT 19,738 and WNS +0.047 ns are context, not a fit prediction.

Unrecovered errors, timeouts, coherence failures and failed restore remain hard stops; no automatic switch to the other arm follows a hard failure without separately defined safe re-admission. Compare actual opportunities and incomplete-run exposure. Repeatable improvement is a qualification candidate, adequate no-improvement weakens only the tested narrow hypothesis, and insufficient or conflicting data are inconclusive.
