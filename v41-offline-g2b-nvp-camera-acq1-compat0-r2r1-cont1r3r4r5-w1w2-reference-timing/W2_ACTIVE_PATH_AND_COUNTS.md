## Reference's reached and conditional paths

`nvp6134_drv.c:767-862` performs ID/revision reads for addresses `0x60/0x62/0x64/0x66`, accepts ID `0x91` or `0x90`, calls `nvp6134_common_init` per detected chip, then `nvp6134_set_chnmode(ch,PAL,NVP6134_VI_1080P_NOVIDEO)` for every channel, then chip-ID-dependent port setup. Source labels `0x90` as the B/C ID, but the physical board's ID/revision read is not available here. For `0x91` the module init calls four `1MUX_FHD` port modes; for `0x90` it calls two `2MUX_FHD` port modes. These mutually exclusive port branches cannot be merged into a single observed path. Source channel `ch=0..3` maps to our CH1..CH4 and private Banks `0x05+ch`, hence Bank 5..8 (`video.c:401,637,1031-1075`).

`nvp6134_common_init` calls `nvp6134_system_init`, writes the paired Bank 3/4 common controls for four channels, and calls `init_acp(ch)` (`video.c:195-232`); `init_acp` reaches `acp_reg_rx_clear`, which has local `msleep(10)` and `msleep(200)` around its Bank 3/4 clear pulse (`acp.c:119-140`). Each default channel-mode call reaches `nvp6134_set_common_value`, then the NOVIDEO branch, then a Bank 9 write, local `msleep(35)`, and final Bank 0 write (`video.c:1099-1183,2068-2136,3536-3596`). NOVIDEO is thus part of the reference module-init path. Our stage-2 table is a fixed AHD 1080p25 configuration with AUTO disabled; it is not an execution of this reference module default. Our source also has its own channel/status and AUTO-related writes, so absence of a named NOVIDEO routine is not evidence that equivalent or different device semantics have been established.

The closest reference mode for our configured target is `NVP6134_VI_1080P_2530` with PAL/`ch=0`: `nvp6134_set_chnmode` → `nvp6134_set_common_value` → `nvp6134_setchn_ahd_1080p2530` → `nvp6134_setchn_common_fhd` → `acp_each_setting` → `eq_init_each_format` → Bank 9 post-mode write, `msleep(35)`, Bank 0 final write (`video.c:1099-1183,3386-3535`; `acp.c:446-550`; `eq.c:78-139`). Its invocation requires a later caller such as `IOC_VDEC_SET_CHNMODE` (`nvp6134_drv.c:431-438`) or a read-dependent detector/user flow; it does not occur automatically in `module_init`. `eq_init_each_format` is reached on this conditional non-NOVIDEO call, but not from the default NOVIDEO call. The kernel thread's apparent detection/EQ body is behind `#if 0` (`nvp6134_drv.c:728-753`) and is inactive. `IOC_VDEC_GET_INPUT_VIDEO_FMT` calls `video_fmt_det` (`nvp6134_drv.c:405-414`); detector results and resulting mode actions remain symbolic because the relevant reads are unknown. No mock read values were assigned to declare a physical reference execution.

## Current 11 events and separate Bank 5 hard failure

All 11 current campaign events are retained in `W2_CURRENT_EVENT_REVIEW.csv`: eight in Banks 5–8 at F2/F4/F5, two in Bank 1 (`98`,`84`), and one in Bank 0 (`EA`). There are ten unique (bank,register) targets because `06/F2` occurs twice. Every listed event is a recovered first-attempt `REGADDR_NACK`; all 11 belong to the 25 complete campaign scans (2,050 entry exposures, 250 group records). The latest campaign did not finish its planned 1,000 scans and does not meet the separate 10,000-scan qualification gate. The `campaign-0022` Bank0/EA event is entry 19, group 3, position 8, `13,169,680 ns` since the historical verify telemetry origin; it is not moved into the first six entries or called immediately post-bank-select.

The reference detector code explicitly selects `0x05+ch` once, then reads F0, F2, F3, F4, F5 in order (`video.c:400-406,636-642`). Thus its F2/F4/F5 source sites overlap eight current target types, but only when the detector function is called. Successive reads do not receive a fresh post-write helper wait unless another write occurs. Bank1/84 has a default NOVIDEO **write** (`video.c:3542-3544`), another conditional 1080P2530 mode-setup **write** (`video.c:3471-3474`), and an optional ADC-clock helper read (`video.c:153-154`); a same-number hit in another bank or an inactive branch is not an active Bank1 read. No Bank1/98 or Bank0/EA read was found in the scoped reference initialization/detector path. `eq.c` has `F4` as an EQ source-select register in Bank `0x0A/0x0B`, not Bank5/F4. No register-value text hit alone was promoted to a bank-qualified executed operation.

The separate next-attempt hard stop is **not** an ordinary data-read event: status `0x00000C18`, first error detail `0x0005FF0A`, valid/failed/retried entries `37/0/0`, 51 accepted transactions, first error index 36, and generation 26 unchanged (`HARD_STOP_RECEIPT.md:4-28`). The failed operation was `0xFF=0x05` bank selection, with no new complete publication. The inherited 18-test offline replay (`74dd150c3438bbea24641cdd8e3bb45e62a5bc65`) establishes that a normal DATA_NACK can produce this signature; it does not identify the hardware cause. A pause **after** an earlier successful write might change entry conditions; a pause **after a successful bank select** can protect the following verify read; a later pause cannot retroactively make this failed bank-select data byte ACK. The historical REGADDR_NACKs and the compatible bank-write DATA_NACK are kept distinct. The older CONT1R2 target set (`08/F2, 06/F5, 00/B0, 07/F4, 05/F2, 07/F0, 07/F5`, authority `501a0dea7588679b0379b88cdc32c8fec2507c3f`) is separate and is not added to the latest 11-event denominator.

## NOVIDEO/AUTO parking lot — `RECORDED_ONLY`

Reference `module_init` sets `det_mode[ch]=NVP6134_DET_MODE_AUTO` and calls the PAL `NVP6134_VI_1080P_NOVIDEO` channel branch (`nvp6134_drv.c:839-845`; `video.c:1099-1183,3536-3596`). Subsequent `IOC_VDEC_GET_INPUT_VIDEO_FMT` invokes the detector (`nvp6134_drv.c:405-414`; `video.c:636-642`) only on that call, with read-dependent actions. Our configured source connects `auto_enable='0'` (`autoinit.vhd:198`); its selected stage-2 Marek stage contains a Bank0/08 write at slot 33, and the later overlay explicitly writes Bank0/08–0B with `auto_byte=0x00` at slots 155–158 (`diagnostics_pkg.vhd:266,390,400-403`). The actual executed initialization therefore contains AUTO-related writes, even though the control input is disabled. These are code observations; no NOVIDEO or AUTO correction, hardware test, or device-behavior equivalence is proposed here.
