# Autonomous scheduler and identities

Scope: DIAG0 offline architecture proposal; no implementation or hardware qualification. Normative decisions apply to the future HW0_DIAGNOSTIC profile. Engineering gate is BLOCKED by the explicitly identified NVP evidence gaps; publication does not promote SSOT.


One validated START controls an entire session run. SCHEDULER_ENABLE=0 executes exactly one cycle, ignoring PAUSE_TIME_MS and CYCLE_COUNT. With scheduler enabled, CYCLE_COUNT=0 repeats indefinitely,1..ffffffff executes that many run/pause cycles. CYCLE_ID starts0 and increments only before the next cycle. The final configured pause is included before COMPLETE; host STOP/ABORT cancels it. PAUSE_TIME_MS=0 is legal; pass through PAUSED for at least one tick.

Each cycle repeats ACTIVE, never snapshots SHADOW again. Per-cycle frame/record totals reset; current-run totals accumulate. RUN_TIME_MS=0 disables time limit; continuous counts plus time0 require host STOP/ABORT and therefore never automatically reach pause. A nonzero run timer starts on the first admitted frame/record, not while initial scanning or frame qualification occurs. It continues during loss/rescan and output drain once started; a rescan does not grant a fresh time budget. Acquisition itself is bounded by LOCK_TIMEOUT_MS and a finite sweep. First of count limit and run-time expiry requests graceful completion. No new frame/record is admitted after that edge; finish the current unit according to its mode. Timer expiry does not cut video at60.000s if a frame is still active.

Pause begins only after protocol-clean drain and backend retirement/quarantine. During pause TVALID=0 and producer admission=0. Pause uses stable AXI time and is independent of host activity. RUN_TIME_MS=60000,PAUSE_TIME_MS=60000,CYCLE_COUNT=0,ENABLE=1 with RECORD_LIMIT=0 gives60s requested record run, record completion/drain,60s pause, repeat. These are minimum clean-boundary ON/OFF durations, not a guarantee of exactly120s wall period under backpressure. The reset RECORD_LIMIT=1 must be overridden to0 for this stress command.

RUN_ID64 increments per successful START. CYCLE_ID64 indexes cycles; SEGMENT_ID64 increments per source-loss/rescan/abort discontinuity and is run-wide, not reset each cycle. A new cycle creates a clean transport epoch and is recorded in the manifest. Epoch remains ABI32 modulo2^32; run/cycle/segment counters do not masquerade as epochs. All totals saturate at2^64-1 and set COUNTER_OVERFLOW, which gracefully ends the session; no silent wrap. ABI32 source/attempt/global fields continue their explicitly specified modulo arithmetic. Finite CYCLE_COUNT compares64-bit completed-cycle count to the32-bit configured target.
