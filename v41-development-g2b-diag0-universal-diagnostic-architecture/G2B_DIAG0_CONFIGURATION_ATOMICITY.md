# Configuration atomicity and commands

Scope: DIAG0 offline architecture proposal; no implementation or hardware qualification. Normative decisions apply to the future HW0_DIAGNOSTIC profile. Engineering gate is BLOCKED by the explicitly identified NVP evidence gaps; publication does not promote SSOT.


One exclusive Linux controller owns command/shadow writes; readers can share a snapshot under the same lock. Writes to SHADOW in any state are allowed and only change the next run. RW registers obey byte enables. START is a full-DWORD command. Capture all shadow fields into a private candidate at START command acceptance, then CONFIG_VALIDATE checks the candidate, not changing shadow. Only successful validation atomically copies candidate to ACTIVE, marks ACTIVE_VALID, increments RUN_ID and begins an epoch boundary. Invalid candidate leaves ACTIVE unchanged, does not consume RUN_ID and emits no data; state ERROR, LAST_COMMAND_RESULT=CONFIG_ERROR and sticky INVALID_CONFIG. Previous terminal counters remain.

START is accepted only in IDLE/COMPLETE/ERROR with no fatal latch, formatter idle and no drain outstanding. Required capability bits must be present. Modes/patterns/rates and every cross-field rule are in JSON. Unknown enums, reserved bits, frame_limit>1000, illegal scan permutation, masked manual input, zero mask, stable_ms=0 or stable_ms>timeout_ms, timeout_ms=0 all reject START. Finite frame/record fields irrelevant to a mode are retained but ignored (reset defaults can both be1). LIVE ignores RATE_MODE for pacing but accepts only PACED_1080P25 as its format-policy selection. Record mode requires MAX_RATE. Video patterns0..2; record patterns0..1. SCHEDULER_ENABLE is0/1. Boolean/enumerated shadow values are validated on START, not during partial writes.

RUN_ID increments for every validated START; CYCLE_ID starts0; SEGMENT_ID starts0. All are64-bit. Each automatic next cycle increments CYCLE_ID, resets per-cycle counters, retains ACTIVE and RUN_ID, and establishes a new transport epoch before output. No START resnapshots halfway through a scheduled run. FRAME_LIMIT/RECORD_LIMIT apply per cycle, with run totals accumulating across cycles. Ordinary rescan preserves counts in both scopes.

COMMAND values:1 START;2 STOP_GRACEFUL;3 ABORT;4 CLEAR_RUN_STATUS;5 SNAPSHOT_COUNTERS. Not bitmasks; combining values is not supported. Writes with BE!=F, unaligned accesses, unknown command or write to RO raise ILLEGAL_COMMAND with no requested side effect. COMMAND reads zero. MMIO write completion only means request transport acceptance; poll COMMAND_SEQUENCE/LAST_COMMAND_RESULT for semantic completion (bridge cannot return a rich AXI write error).

STOP_GRACEFUL latches stop_session, cancels future scheduler cycles; in video finish current admitted full frame and validate its end, in record finish current admitted record. No new unit starts. Drain until accepted TLAST for every committed record and backend release retirement. STOP during PAUSED cancels pause immediately and completes. During scanning/lock/boundary wait cancel candidate, legally finish I2C transaction and drain (usually empty). Timeout of a live graceful frame becomes SOURCE_LOST/invalid frame, not fabricated completion.

ABORT prevents new admissions and sets ABORTED_RUN, increments lifetime/run/cycle ABORT_COUNT once per abort episode. Complete any AXI record already presented, including a stalled beat0; drain fully committed records (no fabricated padding of unvalidated payload). Discard only FILLING uncommitted line; count that failed attempt exactly once. Current video frame is incomplete unless already fully validated and emitted. After clean drain increment segment/discontinuity and transport epoch, with ABI reset accounting, then COMPLETE (aborted result). RUN_ID does not change. Stop/abort never deassert TVALID while stalled. Unbounded TREADY stall can keep DRAINING/ABORTING pending indefinitely; report stall, require host recovery, never cut a packet. Repeated STOP or ABORT is idempotent; ABORT escalates STOP. SNAPSHOT allowed everywhere except RESET; START while busy yields ILLEGAL_COMMAND, never queues another START.

CLEAR_RUN_STATUS only in terminal IDLE/COMPLETE/ERROR clears nonfatal sticky flags/command error and returns IDLE. It does not change ACTIVE, RUN_ID, totals or error evidence snapshot until a new successful START. Fatal ownership/protocol/internal faults cannot be cleared without an explicit external reset/new session; CLEAR returns FATAL_LATCHED. Diagnostic shadow writes never raise BUSY_CONFIG_CHANGE; that flag applies to forbidden direct active writes while busy. No active register is writable.
