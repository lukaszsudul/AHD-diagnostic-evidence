# Synthetic video geometry and exact frame limits

Scope: DIAG0 offline architecture proposal; no implementation or hardware qualification. Normative decisions apply to the future HW0_DIAGNOSTIC profile. Engineering gate is BLOCKED by the explicitly identified NVP evidence gaps; publication does not promote SSOT.


Geometry:1920x1080 progressive, UYVY4:2:2. Pair q (0..959) emits U,Y_even,V,Y_odd. Active line=3840 bytes. A valid frame=1080 line records. Record=4096, transport frame=4423680 bytes, useful frame=4147200 bytes. 1000 frames=4423680000 transport bytes (>2^32), 4147200000 payload bytes,1080000 records. Use64-bit host file offsets/byte/record counters.

FRAME_LIMIT=0 continuous;1..1000 exactly that many complete output frames per cycle;>1000 rejects START. Both LIVE_VIDEO and SYNTHETIC_VIDEO follow this. A frame starts only when line0 is admitted after a qualified vertical/active boundary. FRAMES_STARTED increments then. FRAMES_COMPLETED increments once only after1080 consecutive valid line records with one input/frame identity have all handshaken TLAST and source frame closure confirms there were exactly1080 active lines. A source change, malformed line, drop, extra/missing line or abort invalidates that frame. No partial frame counts. Do not prefetch/admit the next frame when the current admitted frame could satisfy the remaining limit. Rescan retains counts. Count and time limits coexist: first requests graceful completion; time may finish with fewer frames than FRAME_LIMIT and must report TIME_LIMIT, not COUNT_LIMIT.

There is no full-frame FPGA buffer. Validated line prefixes of a frame later found incomplete can already have crossed C2H. The host frame assembler must wait for the frame's complete1080-line proof plus final status/frame-closure evidence before treating it as successful. A finite run's last frame needs the source end boundary; status completion supplies that closure. Frame validity is tracked with a small ordered ledger (frame identity,1080 expected lines, source_closed, error, accepted_record_count), not per-pixel storage. At most one unclosed video frame is admitted by diagnostic control. Real live video cannot be backpressured: whole-record overflow fails the cycle, never silently pretends exact frames were delivered.

Synthetic equivalent marker stream uses FF 00 00 A0 as vertical SAV, FF 00 00 80 as active SAV and FF 00 00 90 as active EAV, matching the existing low-nibble-zero detector. Generate a vertical SAV before the first active line and after line1079. Each line: SAV,3840 payload bytes,EAV, then at least32 filler bytes (80 hex). Header/commit processing may hold synthetic input clock enable; the full transition pipeline freezes consistently. No claim that these simplified markers implement general ITU BT.656 parity: source proof is the exact G2B accepted detector. Initial proving/vertical sequence produces no records. Two byte steps per AXI tick preserve serial ordering; a side-effect requiring a RAM/header cycle stalls the second step until safe, with explicit pending-byte storage.
