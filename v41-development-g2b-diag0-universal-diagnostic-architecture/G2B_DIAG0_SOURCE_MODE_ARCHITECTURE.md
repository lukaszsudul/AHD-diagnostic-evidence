# Three runtime source modes

Scope: DIAG0 offline architecture proposal; no implementation or hardware qualification. Normative decisions apply to the future HW0_DIAGNOSTIC profile. Engineering gate is BLOCKED by the explicitly identified NVP evidence gaps; publication does not promote SSOT.


SOURCE_MODE values are exactly 0 LIVE_VIDEO, 1 SYNTHETIC_VIDEO, 2 SYNTHETIC_RECORD. All are elaborated into one future image. Repeated START operations snapshot different modes without reprogramming. RUNTIME_MODE_SWITCH_WITHOUT_REPROGRAMMING = YES is the architecture contract, not a statement that firmware exists.

Recommended architecture: retain the PRODUCT live producer and its four dual-clock slots. Add one separate four-slot synchronous diagnostic ring, shared by the two synthetic modes. Extract the existing AXI formatter into one common hardware block, with selected RAM read data and a normalized owned-record descriptor as inputs. A descriptor includes slot/generation/epoch, locked header metadata, and ring identity (internal only). It returns release to the selected ring only on accepted beat 511. The full wire image is fixed before beat 0. Logical output channel count is always one. No round-robin between sources.

LIVE_VIDEO injection is unchanged: top-level G2B_ONECH_C2H source_byte=nvp_data_byte after NVP_PHYSICAL_FRONTEND. The current monolithic module internally repeats qualification; it does not stream through the legacy bt656_record_producer module. Preserve its marker/length, packing, header, commit and CDC ownership behavior while extracting the formatter interface.

SYNTHETIC_VIDEO injection: post-physical-frontend equivalent byte input to a diagnostic instance of the G2B qualification/line-producer state transition logic, processing two ordered bytes per axi_aclk. It performs the same G2B marker, active-line, line-length and frame interpretation, then packs payload, writes header and commits to diagnostic slots. Reuse the source transition definition and require step-equivalence tests; this is another hardware instance, not coverage of the live parser's physical flops or CDC path. Marker pipeline and state advance share a clock enable; all parser state freezes when synthetic input is paused.

SYNTHETIC_RECORD injection: 64-bit write/commit interface of the diagnostic ring, before common owned-record scheduling and formatter. Generate 480 payload words plus eight header words; commit only after all 488 stored words are complete. It bypasses both video parsers. Padding is generated by the common formatter exactly as PRODUCT.

The accepted PRODUCT four-slot ring is NOT_SHARED with synthetic producers. The extra four-slot ring maximizes formatter/AXI reuse while avoiding a write-clock mux or dependence on absent NVP clocks. This is a deliberate coverage limitation; synthetic tests cannot sign off PRODUCT source-domain ownership CDC. The alternative of sharing its write port across independent clocks is rejected. A shared ring with a new live CDC packet bridge would require deeper changes and is deferred.

No streaming at reset. LIVE capability and four-input/scan/rescan capability advertisement remain disabled until the evidence-backed NVP prerequisites in the audit are closed. Synthetic capabilities describe implementable architecture only; they are not present in PRODUCT.
