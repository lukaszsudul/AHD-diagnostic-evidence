# Manual selection, scan and loss policy

Scope: DIAG0 offline architecture proposal; no implementation or hardware qualification. Normative decisions apply to the future HW0_DIAGNOSTIC profile. Engineering gate is BLOCKED by the explicitly identified NVP evidence gaps; publication does not promote SSOT.


This control algorithm is frozen; its NVP classifier/board adapter remains blocked by B1/B2. Logical input n means NVP decoder n+1; physical connector naming needs B2. SCAN_MASK applies to manual and auto modes. SCAN_ORDER is four 2-bit entries, low pair first, each of0..3 exactly once; default E4 means0,1,2,3. PREFERRED_INPUT=0..3 or FFFFFFFF (none). Skip a masked preferred input; do not test it twice. A zero mask is invalid.

Manual: reject number>3 as INVALID_CONFIG/detail INVALID_INPUT; reject masked selected input as INVALID_CONFIG/detail MASKED_INPUT, with no routing or output. START waits for INIT_DONE with no INIT_ERROR, bounded by LOCK_TIMEOUT_MS. Before any route transaction, gate frame admission. Read present/lock/format for selected input; route only an eligible candidate. No signal persists until the per-candidate deadline then NO_INPUT_AVAILABLE. Present but unstable lock yields INPUT_LOCK_TIMEOUT. Known wrong format yields INPUT_FORMAT_UNSUPPORTED; unknown classifier validity fails closed. A partial initial frame is discarded.

Auto algorithm: SCANNING obtains status for the preferred enabled input first, then enabled entries in SCAN_ORDER. Each candidate gets a LOCK_TIMEOUT_MS deadline including status reads, routing and stability; absent input may be skipped immediately after a valid no-video read. Unsupported format is recorded and skipped. ROUTING obtains exclusive I2C owner and verifies C2/C8 control. WAIT_LOCK requires valid sampled present, AGC/CLAMP/H-lock and format1080p25 continuously across LOCK_STABLE_MS. Poll candidate status at most every10ms (one batch must complete within10ms); missing/stale sample invalidates stability. Timeout or loss restarts/advances candidate. WAIT_FRAME_BOUNDARY discards all lines until a qualified vertical-to-active transition. Validate one complete1080-line frame and 40ms period (39.6..40.4ms) before admitting the following full frame. A positive geometric check supplements, never replaces, authoritative NVP format status.

Scan exhaustion ends in ERROR with SCAN_EXHAUSTED and NO_INPUT_AVAILABLE; retain last candidate, per-input failure and first failure coordinates. One sweep per initial scan or loss event; no hidden infinite retry. Once locked do not rotate among otherwise valid cameras.

LOSS_POLICY_STOP=0 default. Loss event means active present/lock false, unsupported/unknown format, no completed status batch for>20ms, or no valid frame boundary within LOCK_TIMEOUT_MS. Set SOURCE_LOST; freeze failure input/frame/line/record/cycle/segment; mark the current unclosed frame invalid. Complete any already-presented AXI record, drain other fully committed records, discard uncommitted line, and reach ERROR after a clean record boundary. Previously completed frames remain counted. No full-frame buffering is claimed: emitted prefix records cannot be retracted; host discards that frame using SOF progression and the error manifest.

LOSS_POLICY_RESCAN=1: same invalidation/drain first, increment SEGMENT_ID and DISCONTINUITY_COUNT once per loss transition, retain RUN_ID/CYCLE_ID and completed-frame totals, then scan again. Preserve epoch for an ordinary rescan with healthy source-domain handshakes; mark next committed same-epoch record DISCONTINUITY. If source clock disappearance requires quarantine and transport reset, create new epoch, clear old pending flags per ABI and describe transition out of band; do not carry a stale discontinuity flag into the new epoch. Never combine sources into one frame. If the cycle already reached its frame/time limit, finish the cycle instead of rescanning. Source change does not reset frame count or renew run-time allowance.

All cycles rescan/relock from ACTIVE configuration. Background status collection is serialized with routing. Cache four inputs with validity and sample time; a not-yet-read input is UNKNOWN, never asserted absent. During RUNNING prioritize active input at10ms; update others opportunistically, without claiming their cached state is current.
