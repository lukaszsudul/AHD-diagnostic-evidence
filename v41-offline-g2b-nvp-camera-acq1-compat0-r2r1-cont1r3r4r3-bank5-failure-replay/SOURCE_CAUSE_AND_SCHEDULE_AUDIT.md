Actual top/master settings are `CLK_HZ=62,500,000`, `I2C_HZ=25,000`, with no timeout overrides. Thus the master's default `SCL_TIMEOUT_CYCLES=1250`, `BUS_IDLE_TIMEOUT_CYCLES=62500`; the divider is 1250 and a master tick is 1251 nominal 16 ns clocks. The pin-level simulation asserted these exact elaborated values. The top's `autonomous_clk` is `axi_aclk`; the wrapper passes `i2c_error_cause`, `i2c_timeout`, `i2c_success`, `i2c_done` and registered `i2c_cmd_accepted` to the scanner without a numeric cause conversion. The simulation omits the wrapper as logic because these direct ports reproduce this wire path; that omission is explicit, not an assumption about source mapping.

At command acceptance the master clears `success`, `timeout`, `error_cause` and increments its sequence (240–254). The normal ACK failures set raw `1` in write-address ACK (310–320), raw `2` in register-address ACK (331–344), raw `4` in data-byte ACK (354–360), and raw `3` in repeated-start read-address ACK (379–390). A held SCL sets timeout and raw `5` (281–287); idle/STOP timeout sets timeout and raw `6` (267–272, 415–419). STOP completion sets `success=!command_error&&!timeout` and `done=1` (408–414). Abort-release sets `success=0`, `done=1` (276–280). The master's default invalid-state arm enters abort-release without assigning a fresh cause (424), so a cause-zero failure is possible only under an illegal-state/interface fault, not an ordinary legal transaction. Reset clears all completion fields (211–232); a mid-transaction reset does not itself demonstrate the recorded completed-command signature. This is source-path analysis plus one synthetic interface witness, not exhaustive formal reachability.

The scanner's `frozen_error_code()` maps raw 1/2/3 with timeout 0 to scanner 1/2/3. With timeout 0, raw 4 and every other unhandled code map to scanner `0xA`. With timeout 1, only raw 6 maps to scanner 5; every other raw nibble maps to scanner 4. Scanner error `4` is `SCL_TIMEOUT`, **not** raw master `DATA_NACK=4`. The complete 32-row table is in `MASTER_TO_SCANNER_CAUSE_MAP.csv`; mock-only combinations are marked as such. `record_first_error()` stores only the first failure as `{zero,bank,register,zero,error}`. The failed Bank5 select calls it with `(entry_index, 0x05, 0xFF, frozen_error_code(...))` (726–734).

The frozen manifest gives group starts `0,1,4,11,27,37,48,59,70,81` and counts `1,3,7,16,10,11,11,11,11,1`. Groups 0–4 cover 37 entries, indices 0–36. At the end of index 36, the scanner advances `group_index` but does not load `entry_index=37` until Bank5 selection and verification succeed (802–825, 741–767). A selection failure therefore records retained `first_error_index=36`. Command-level accounting is `1` entry-bank read + `10` select/verify commands for five complete groups + `37` entry reads + `1` failed Bank5 select + `2` successful restore commands = `51`. A successful select followed by failed verify adds one command and yields `52`. These counts are accepted master commands, not I2C bytes or host MMIO reads. T02/T06/T15/T16 independently measured the respective counts.

On select failure the scanner enters restore, writes the original bank, reads it back, and sets `restore_verified`. It then enters `ERROR_NOT_PUBLISHED`, so generation does not advance (872–928, 953–958). `scan_flags` is filled with the final command count and restore bit, with complete-publication bit clear. One qualified `ACK_CLEAR` returns idle without a command or generation advance. Entry read failures alone have the one-retry rule; group selection has no retry (827–869 versus 726–739). A restore failure instead locks out the bank context; T13 showed status `0x00000C58`, count 50 and no verified exit bank, distinct from the historical receipt.
