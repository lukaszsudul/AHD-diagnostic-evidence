# G2B-HW0-DRV1 platform-module collision audit

## Disposition

```text
PLATFORM_XDMA_MODULE=PRESERVED_UNCHANGED
AHD_CANDIDATE_MODULE=xdma_ahd_pcie
MODULE_NAME_COLLISION=NO
BUS_ALIAS_COLLISION=NO
CLASS_NAME_COEXISTENCE=NOT_PROVEN_OFFLINE
R3_PLATFORM_MODULE_POLICY=REMAIN_UNLOADED
```

The installed platform-bus module was inspected read-only. Neither it nor the
AHD candidate was loaded for this audit, and coexistence was not tested.

## Name and alias analysis

The candidate's behavior-preserving Kbuild rename changes both its output file
and internal module name to `xdma_ahd_pcie`. Static `modinfo` confirms that
identity, so the kernel module-name collision with installed internal name
`xdma` is `NO`.

The two modules also occupy different bus-discovery namespaces:

- the installed module has only `platform:xdma`;
- the AHD candidate has only the exact subsystem-specific PCI alias.

Consequently a `platform:xdma` modalias cannot select the AHD candidate, and an
AHD PCI modalias cannot select the installed platform driver.

## Symbol and class audit

The candidate's ELF symbol inventory reports 89 defined global symbols and 134
undefined kernel references. Ordinary global symbols inside a module are not,
by themselves, exported kernel symbols. Static section inspection found no
candidate `__ksymtab`/`__kstrtab` export section; thus the offline evidence does
not demonstrate a candidate exported-symbol namespace collision.

This does not establish runtime coexistence. The candidate intentionally
retains upstream `XDMA_NODE_NAME="xdma"`, and `xdma_cdev_init` creates class
`xdma`. The installed platform module's internal implementation was not loaded
or co-probed, and collision behavior for a simultaneously existing class or
other runtime resource has not been proven. A compressed-file static identity
comparison cannot substitute for that runtime test.

Therefore:

```text
EXPORTED_SYMBOL_COLLISION_DEMONSTRATED=NO
EXPORTED_SYMBOL_COEXISTENCE_PROVEN=NO
XDMA_CLASS_NAME_SHARED_BY_CANDIDATE=YES
SIMULTANEOUS_LOAD_SAFETY=UNPROVEN
```

## R3 control

The future R3 plan must require the installed platform module to remain
unloaded. It must load only the exact sealed path to `xdma_ahd_pcie.ko`, never
generic `modprobe xdma`, and must stop if either module is unexpectedly present
in the live module set. No coexistence test, cleanup, unload, or rollback is
authorized by DRV1.

## Audit boundary

The result proves distinct filenames, internal names, and bus aliases while
preserving the installed platform file unchanged. It does not prove that both
modules can coexist, that class creation will succeed, or that the candidate
will probe an endpoint. Those are runtime questions outside DRV1.
