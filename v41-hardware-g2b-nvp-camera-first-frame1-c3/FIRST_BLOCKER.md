# FIRST-FRAME1 first blocker: safe C2H reader unavailable

The task stops **before DUT admission and before stream enable** at `BLOCKED_SAFE_C2H_READER_UNAVAILABLE`. FIRST-FRAME1 §3 requires a demonstrably executable, time-bounded end to pending C2H I/O before enabling the stream. No existing helper or new userspace reader on the unchanged qualified driver currently meets that gate for a one-session 10-second/32-MiB capture.

The qualified module SHA-256 is `E8B48E342C80B019BB4884FD7AF16AB1049BC60266101E6E4A8B6514AEEB3D77`. Its sealed Build A manifest pins Xilinx upstream `b8466090b4e812e191da9e9305ffb11cb7ace768`; the build patch changes PCI match, module label and Kbuild compatibility only. Local upstream source commit/tree were verified and `cdev_sgdma.c`/`libxdma.c` match their pinned Git blobs.

* **Prequeued AIO:** A real prior capture under this driver family left a guard AIO in kernel `read_events` after stream OFF and five-sample FPGA quiescence PASS. The descriptor, module reference and task locks remained held. This is documented in `G2B_HW0_PRODUCT_R3R4R6R1_CLEANUP_RECEIPT.md` at evidence commit `16972c27a132ef1963d9f46b59e2feeaff349e82`. The historical `xdma_st_c2h_multiqueue.c` was not executed and does not establish cancellation. The current driver has no demonstrated `ki_cancel`/bounded `io_cancel` completion contract for this path.
* **Synchronous `read()`:** `cdev_sgdma.c:376-425` passes the 10-second default C2H timeout to `xdma_xfer_submit`. `libxdma.c:3553-3696` holds `desc_lock` while queuing and waiting, so several synchronous readers do not prequeue independent requests. A timeout can occur per internal transfer; its abort/engine-stop steps can fail before transfer destruction and user-buffer unmap. The 10-second driver timeout therefore does not prove safe drain inside a session limited to 10 seconds including drain. The device has no `.poll` operation or effective `O_NONBLOCK` path for this read; `O_TRUNC` only sets EOP flush, making line-sized reads rely on userland requeue gaps. Four 4096-byte FPGA slots cannot by themselves certify lossless serial line reads.

No MMIO write, C2H read, ACQ operation, CH1 scan, module load, SSH connection, SRAM program or DUT reboot was performed. The physical camera gate was requested, but its answer is not needed to establish this earlier blocker. W4's historical CH1 NOVID=1 is not a fresh signal measurement.

**Next concrete action:** establish and qualify a bounded C2H completion/cancellation and drain procedure for the unchanged qualified driver under the 10-second/32-MiB contract, or separately authorize a driver remedy. Only then open a new scoped hardware attempt with current camera confirmation. Do not use an AIO guard request as an unproven cleanup mechanism.
